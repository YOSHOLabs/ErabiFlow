## YouTube: 4分のデモ進行

| 時間 | 操作・映像 | 説明 |
| --- | --- | --- |
| 0:00–0:25 | 起動、全体画面 | ErabiFlow Beta 0.1.0。編集前の素材整理を支援する |
| 0:25–0:50 | 横または縦の自作動画を追加 | 元動画は端末内で処理する。初回だけモデル等の大容量取得が必要 |
| 0:50–1:15 | ローカル解析開始、進捗 | 解析はCPUで時間がかかる。待ち時間は「解析待ちを省略」と明示して編集 |
| 1:15–2:00 | 見どころ候補と根拠、KEEP／没 | AI判断を読み、人が使う区間を選ぶ。候補は正解を保証しない |
| 2:00–2:50 | IN／OUT、分割、並べ替え、再生 | 必要な順番のラフカットにする |
| 2:50–3:30 | MP4、EDL、SRT、JSON、CSVを書き出す | 元画角のラフカット。字幕の焼き込みや仕上げは編集ソフト側 |
| 3:30–4:00 | 出力ファイルとDownload／Issues案内 | NLE実importを確認できた場合のみその画面を追加。未確認ならファイル出力までを見せる |

事前に初回取得を終え、同じ動画で解析と書き出しが最後まで通ることを確認します。取得済み・解析時間短縮の編集を隠しません。完成映像の自動編集、Premiere/Resolveプラグイン、未確認の互換性を説明しません。

## YouTubeで伝える7項目

1. 長尺動画の候補整理とラフカット受け渡しを支援するWindowsツールを作った。
2. 編集に入る前に必要な区間を選ぶ作業を支援したい（制作者本人の動機と合うか収録前に確認）。
3. 候補と根拠、KEEP／没、IN／OUT、分割・順番、MP4と受け渡しデータを使える。
4. 人が判断するツールであり、完成動画を完全自動編集するものではない。
5. 動画・音声・字幕の解析はローカル。初回は約1.65GiBの取得がある。
6. Beta 0.1.0、Windows 11 x64、未署名、AI結果は確認が必要。
7. 公開後の公式Releaseから取得し、GitHub Issuesへ不具合・感想を送れる。

## 公開作業順

1. 技術報告、EULA判断、クリーンPC結果を確認し、公開を承認する。
2. 検証済みRC SHAを指すタグでGitHubのprereleaseを作り、検証済みMSIとSHA256SUMS.txtを添付する。
3. Release NotesとREADMEの「公開準備中」を実態に合わせて更新する。古いMSIを混ぜない。
4. 実ダウンロードとSHA-256の一致、Issue窓口を確認する。
5. 最終動画・画像を確認し、YouTube/Xのリンクを差し替えて投稿する。
